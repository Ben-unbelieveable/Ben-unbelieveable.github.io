Subgraph与组合

发表于 2026-08-10 | 更新于 2026-08-28 | 分类于 Agent工程 ， LangGraph
Subgraph 嵌套 compile：多 Agent 分工、复用子流程与主图组合方式。

「检索子流程」要在客服 Agent 和内部工具里复用——复制节点会双份维护。Subgraph 把子流程单独 compile，再作为单节点挂到主图，checkpoint 按 namespace 隔离。

1. 定位

维度 内容
角色 模块化图组合
输入 → 输出 子图 compile 产物 → add_node("sub", subgraph)
核心 API 嵌套 compile()、共享 State 字段
依赖 LangChain 无

3. invoke 生命周期

子图 superstep 计入主图调度；checkpoint ns 分子空间（见 checkpoint_ns 篇）。

4. 原理

4.1 共享 State schema

主图与子图 State 字段需兼容；子图只应写自己负责的字段。

4.2 编译顺序

先 sub = sub_builder.compile()，再 main_builder.add_node("sub_research", sub)。

4.3 主图 Saver、子图自动 ns

通常只在主图 compile(checkpointer=cp)。子图 compile() 不传 Saver 时继承同一实例：invoke 仍是 get_tuple / put，只是进子图节点时框架把 checkpoint_ns 改成 节点名:task_id，写入 storage[thread][该ns]。子图再传一个独立 Saver 会让恢复对不齐同一棵树。

7. 易踩坑

  1. 子图 State 字段与主图不一致：合并失败或丢字段。
  2. 子图单独 compile 又传独立 checkpointer：恢复顺序混乱。
  3. 子图过大：调试难，应拆清晰 IO 边界。

小结

  • Subgraph = compile 后的图当节点；适合复用检索/审批子流程。
  • State 字段在主子图间共享 schema。
  • 主图绑一个 Saver；子图共用该实例，靠自动 checkpoint_ns 分抽屉。
